# Lenses: Belief Systems for Reflection

This document explains what lenses are, how they're organized, and how to contribute new ones.

---

## What is a Lens?

A **lens** is a belief system, philosophical framework, or psychological approach that people declare as their own. When you say "I'm Buddhist" or "I'm Jungian," you're claiming a lens.

In reflection-skill, lenses serve two purposes:

1. **During journaling (capture layer):** Your declared lenses shape what the agent recognizes as journal-worthy
2. **During reflection (interpretation layer):** Your lenses are applied to past entries to deepen understanding

---

## The Universal Questions

Every lens, regardless of tradition, illuminates answers to some of these universal questions:

- **How should I live?** — Right action, integrity, values alignment
- **What's true?** — Reality, illusion, what we get wrong about the world
- **How do I deal with suffering?** — Pain, difficulty, adversity, loss
- **What matters most?** — Meaning, purpose, what's worth pursuing
- **Who am I really?** — Identity, ego, your deepest self
- **How do I find peace?** — Freedom, wholeness, contentment, liberation

No single lens answers all questions. A lens is valuable precisely because it illuminates some questions deeply while leaving others to other frameworks.

## Anatomy of a Lens Definition

Each lens file includes:

1. **Framework** — Clear, accessible definition. No jargon without translation.
2. **Universal Questions** — Which of the six questions does this illuminate?
3. **Inference Rules** — What patterns help you see when reading journal entries?
4. **Epistemological Grounding** — What does this lens see well? What does it miss?
5. **Reference Materials** — Authoritative sources for learning more
6. **Plain Language Translation** — What would someone actually experience practicing this?

## Contributing a New Lens

### Research → Writing → Review → Merge

1. Study authoritative sources deeply
2. Draft the lens file following the template
3. Translate all jargon to plain language
4. Test inference rules with sample entries
5. Open a pull request with your sources
6. Community review and feedback
7. Merge when consensus is reached

---

## Quality Standards

✓ Clear, accessible framework definition
✓ Mapping to universal questions
✓ Practical inference rules
✓ Honest about blind spots
✓ Authoritative reference materials
✓ Plain-language translation

✗ Personal syntheses (unless labeled as such)
✗ Jargon without explanation
✗ Overstated claims about the tradition
✗ Dismissal of other traditions
